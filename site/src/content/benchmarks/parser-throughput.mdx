Замерена функция `schedule_parser::parse_file` на четырёх файлах `.xls` из каталога `tables/`. В таблице показаны медиана и 95-й перцентиль времени на один файл. Последняя строка — один последовательный разбор всех четырёх файлов.

| Набор | Размер входа | Записей занятий | Медиана | p95 |
|:--|--:|--:|--:|--:|
| Учебная неделя 2 | 115 712 байт | 178 | 0,472 мс | 0,586 мс |
| Учебная неделя 3 | 115 200 байт | 161 | 0,446 мс | 0,492 мс |
| Учебная неделя 4 | 118 272 байта | 179 | 0,468 мс | 0,509 мс |
| Учебная неделя 5 | 119 808 байт | 186 | 0,480 мс | 0,517 мс |
| Все четыре файла | 468 992 байта | 704 | 1,967 мс | 2,074 мс |

Каждый отдельный файл разобран 50 раз для прогрева и 1 000 раз для замера; затем так же измерен пакет из четырёх файлов. Использовалась оптимизированная сборка, файлы оставались в файловом кэше ОС. Результат описывает только чтение и разбор локальных книг: без запуска бота, запросов к базе данных и сетевой доставки.

Повторить замер из корня репозитория:

```sh
cargo run --release -p schedule-parser --example parse_benchmark -- tables/*.xls
```
