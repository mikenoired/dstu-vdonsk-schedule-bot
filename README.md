# Расписание ДГТУ

Проект разделён на библиотеку `schedule-parser` и CLI `schedule`. Парсер читает книги Excel `.xls`/`.xlsx` и выдаёт пары в нормализованной модели с датой, временем, группами, дисциплиной, видом занятия, преподавателем и аудиторией. CLI фильтрует эти данные и выводит JSON.

## Запуск

Если в `tables` лежит ровно один файл `.xls` или `.xlsx`, путь определяется автоматически. Иначе передайте `--input`.

```sh
cargo run -p schedule-cli -- week --group ИС11В
cargo run -p schedule-cli -- room --room 303/2
cargo run -p schedule-cli -- day --date 28.09.2026
```

По умолчанию CLI выводит JSON. Флаг `-pretty` (также доступны `--pretty` и `-p`) переключает `stdout` на читабельный список с эмодзи. Заголовок указывает группу, аудиторию или дату в зависимости от запроса; выбранный фильтр не дублируется в строках занятий. JSON при этом можно отдельно сохранить через `--json`, а список — в JPEG через `--jpeg`:

```sh
cargo run -p schedule-cli -- week --group ИС11В -pretty --json schedule.json --jpeg schedule.jpg
```

Шрифт с кириллицей определяется из стандартных путей macOS/Linux. Если его нет, укажите TTF явно через `--font /path/to/font.ttf`. Общие группы из заголовка через `/` доступны при запросе по каждому из перечисленных обозначений.

В JPEG занятия сгруппированы по дням. Вид пары, преподаватель и аудитория выделены цветными chips.

## JSON

Каждый элемент результата содержит `groups`, ISO-дату `date`, день недели, номер пары, время начала и окончания, дисциплину, вид занятия, преподавателя, аудиторию и исходное описание ячейки. Продолжения объединённых ячеек аудиторий включаются в диапазон времени одной пары.
Аудитория `ДОТ` нормализуется до `Удалённо`; запрос по аудитории принимает оба варианта.

## Telegram-бот

Бот запускается отдельным пакетом `schedule-bot` и хранит пользователей, опубликованные версии расписания, состояния диалогов и очередь уведомлений в PostgreSQL. Счётчики rate limit хранятся в Redis, а оригиналы опубликованных Excel — в S3-совместимом бакете. Миграции применяются при старте.

### Локальный запуск

Создай бота через BotFather, подними PostgreSQL и задай переменные из `.env.example`:

```sh
cargo run -p schedule-bot
```

`ADMIN_BOOTSTRAP_TOKEN` используется только для создания первого администратора и принимается один раз на базу данных. Создай случайный токен, например `openssl rand -hex 24`, и открой:

```text
https://t.me/<bot_username>?start=bootstrap_<ADMIN_BOOTSTRAP_TOKEN>
```

После первого входа администратор может создавать одноразовые ссылки `/admin_link`; они действуют 15 минут.

### Railway

Подключи репозиторий как сервис с корнем проекта и корневым `Dockerfile`, добавь PostgreSQL, Redis и S3-совместимый бакет. Укажи для бота:

- `TELEGRAM_BOT_TOKEN` — токен BotFather;
- `DATABASE_URL` — reference variable на `DATABASE_URL` сервиса PostgreSQL;
- `REDIS_URL` — URL Redis-сервиса Railway;
- `AWS_ENDPOINT_URL`, `AWS_S3_BUCKET_NAME`, `AWS_DEFAULT_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` и `AWS_S3_URL_STYLE` — параметры Railway Bucket. При подключении выбери стиль `AWS SDK (Generic)`; для новых Railway Buckets `AWS_S3_URL_STYLE` обычно равен `virtual`;
- `ADMIN_BOOTSTRAP_TOKEN` — случайный токен для первого администратора;
- `BOT_TIMEZONE` — необязательно, по умолчанию `Europe/Moscow`.

Бот получает обновления через long polling. Отдельный HTTP endpoint на `PORT` (Railway задаёт его автоматически, локально по умолчанию `3000`) отвечает на `/healthz` и `/metrics`. `/healthz` проверяет PostgreSQL и Redis; `/metrics` отдаёт Prometheus-совместимые счётчики очереди уведомлений, отправок, rate limit и ежедневного планировщика. Для просмотра прикладной статистики без внешнего сервиса администратор может вызвать `/stats` в личном чате: бот пришлёт JPEG-дашборд с периодами 30 минут, 1 час, 24 часа и 7 дней. История событий хранится в Redis по минутам и часам с автоматическим удалением старых точек. На старте бот повторяет подключение к PostgreSQL и применяет миграции.

Пользователям, которые выбрали группу в личном чате бота, автоматически приходит расписание на завтра в 21:00 и на сегодня в 07:00 по `BOT_TIMEZONE` (по умолчанию `Europe/Moscow`). Доставка проходит через очередь уведомлений и защищена от дублей при перезапуске сервиса. В сообщении есть пометка «План на завтра» или «Доброе утро! Расписание на сегодня», дата, день недели и группа; если пар нет, бот сообщает об этом.

### Групповые чаты

Добавь бота в группу и назначь его администратором без лишних прав: Telegram позволяет надёжно проверять, кто меняет настройки группы, только если бот является администратором. После этого администратор чата привязывает учебную группу командой `/setgroup ИС11В`. Участники могут запросить расписание командами `/today`, `/week`, `/day 28.09.2026` и посмотреть привязку через `/group`. Привязку можно заменить повторным вызовом `/setgroup`.

Для проверки прав администратора чата боту нужен статус администратора с минимальными разрешениями. Telegram будет доставлять ему все сообщения группы, но приложение обрабатывает только slash-команды: обычный текст игнорируется и не сохраняется. Участники могут вызывать команды с явным упоминанием бота, например `/today@имя_бота`.

Для защиты от спама действует Redis-скользящий лимит: до 6 входящих событий от пользователя за 10 секунд во всех его чатах и до 24 slash-команд на групповой чат за 10 секунд. В личке при превышении бот показывает одно предупреждение за 30 секунд, а в группе просто пропускает запросы до восстановления лимита.

Если bucket credentials отсутствуют или настроены неверно, бот всё равно запускается, но публикация Excel временно недоступна; при загрузке администратор получит сообщение об ошибке.

В личном чате кнопка «🔔 Уведомления» переключает личные уведомления о ежедневном расписании и изменениях расписания. В групповом чате администратор может отключить команды расписания командой `/disable`; повторный `/setgroup` включает их снова. Автоматические рассылки отправляются только в личные чаты.

### Публикация расписания

Администратор отправляет боту `.xls`, `.xlsx` или `.xlsb` размером до 15 МБ. Бот проверяет, что файл парсится в расписание одной недели, вычисляет затронутые группы и дни, затем ждёт подтверждения. Совпадающая неделя считается актуализацией; другой недельный период — новой неделей. Неизменённый разбор не публикуется повторно, а файл из заменённой версии недели отклоняется, чтобы исключить случайный откат. Подтверждение публикует новую версию в транзакции и ставит студентам уведомления в очередь.

Если нужно перепарсить уже опубликованное текущее расписание после обновления парсера, администратор может повторно отправить тот же Excel. Бот пропустит его в предпросмотр только если новые записи отличаются от текущей версии; прежние файлы, которые уже заменены более новой версией, по-прежнему отклоняются.
